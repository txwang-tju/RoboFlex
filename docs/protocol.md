# 知意随行 RoboFlex JSONL 机械臂桥接协议 v1

这是本代码包定义的参考协议，不是对开发者已有固件协议的推测。Python 主机发送意图确认后的关节轨迹；控制板负责电机／舵机映射、本地限位、插补、反馈、停止和失联保护。

## 传输与单位

- 串口默认 115200，或 TCP；一行一个 UTF-8 JSON，行尾 `\n`。
- 每个请求 `id` 唯一递增。主机最多保留一个等待完成的动作请求，停止可以抢占它。
- 关节角为数学坐标系下的**度**，不是原始舵机刻度。顺序 `[base_yaw, shoulder, elbow, wrist_pitch]`。
- 距离／夹爪开口为 mm，时间为秒。固件必须验证有限数、范围和最大速度。
- 每条回应都带**实测／反馈的当前关节角**。无反馈舵机的目标值不应伪装为实测值；这类硬件应另写适配器并明确状态可观测性限制。

## 握手

主机：

```json
{"op":"hello","id":0}
```

固件回应：

```json
{"id":0,"status":"done","protocol":"roboflex-jsonl-v1","simulated":false,"capabilities":["move_joints","gripper","stop","watchdog","state"],"joints_deg":[0,95,-120,-65]}
```

上面的关节角只是报文示例。真实固件必须读取自己的当前姿态。Python 模拟器的 `simulated=true` 仅用于标记本地仿真。

## 关节运动与夹爪

```json
{"op":"move_joints","id":17,"joints_deg":[-12.5,75.0,-95.0,-70.0],"duration_s":0.20}
{"op":"gripper","id":18,"width_mm":35.0,"duration_s":0.40}
```

固件收到动作后可内部排程，但只有**动作完成并且反馈在约定容差内**才回复：

```json
{"id":17,"status":"done","joints_deg":[-12.5,75.0,-95.0,-70.0]}
```

拒绝／故障：

```json
{"id":17,"status":"error","error":"joint_limit","joints_deg":[-12.0,74.5,-94.5,-70.0]}
```

不要在“已收到”时回复 `done`。若平台现有协议区分 `accepted` 与 `completed`，修改 Python 适配器等待 `completed`。当前实现只接受最终 `done`，并检查关节跟踪误差；超时或错误会停止后续队列。

## 心跳与停止

```json
{"op":"heartbeat","id":19}
{"op":"stop","id":20,"reason":"user_cancel_or_withdraw"}
```

心跳无需回复。**固件必须独立设置看门狗**，在超过约定时间没有收到有效心跳时中止运动；进程退出、串口断线和网络断开时也不能继续排空旧队列。默认主机每约 0.1 秒发送心跳；主机观测看门狗默认 0.45 秒，固件超时应按实测控制周期协同设置。

`stop` 必须优先于正在执行的动作与缓存队列，停止继续推进，并保持当前夹爪状态。应按本机构设计的受控停止方式处理，不能简单把“松开全部舵机”当作停止。确认后回复当前关节状态：

```json
{"id":20,"status":"done","joints_deg":[-12.2,74.7,-94.9,-70.0]}
```

Python 会丢弃被取消动作的迟到 ACK，不再推进旧计划。停止 ACK 缺失或通信断开时标为 `FAULT`，主机不假定机器人已经安全停止；失联停止由本地控制器承担。

软件复位不自动把机器人移回原位。中止后先处理姿态和夹持物、恢复到实测原位，再重新建立会话。

## 与平台现有控制板对接

若已经有 `SET_SERVO(channel,pulse)` 或 RT-Thread 设备接口，保留原驱动，在控制板或上位机桥接层中完成：数学关节角 → 零位偏置／正负方向 → 舵机脉宽。不要在不知道连杆长度和舵机方向的情况下使用默认参数。

本包只提供 Python 控制端与 Python 模拟固件。STM32／ESP32 实机固件需要结合板型、舵机、电源和驱动协议实现，尚未在平台的实机上验证。
